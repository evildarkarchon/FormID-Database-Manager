1 · Advanced Mode becomes a projection inside the Plugin List

Strong in-process

  • Core/Services/PluginList.cs:96-125 RefreshAsync(source, advancedMode) · :403-421 Base Game Plugin filter in discovery · :440 MaterializeSelectedPluginNames

Before: each toggle is a full refresh

Off → On does not restore base selections dropped at On → Off.

After: discovery held once, mode projects it

Rediscovery happens only when the Plugin List Source changes.

Problem
The glossary calls Advanced Mode a display mode, but it is built as rediscovery from disk. Each toggle rescans, posts a message, and permanently drops selected Base Game Plugins.
Solution
The Plugin List keeps the unfiltered discovery for its source and applies the Base Game Plugin filter as a projection. Advanced Mode becomes a Plugin List intent with no I/O.
Wins
  • Locality: one filter, one owner
  • No disk scan per toggle
  • Selection rule decided once, explicitly
  • Toggle tests need no async discovery
  • Three Advanced Mode copies → two
Consistent with ADR-0009 (the Plugin List publishes one coherent revisioned state) and ADR-0011 (Game Context still owns the Advanced Mode state and forwards the intent). Open question for grilling: should hidden-but-selected Base Game Plugins stay selected (and reach a run), or only be remembered?

Stays inside ADR-0001 (the Store owns SQLite). This merges the morning review's candidate 5 with three new rollback sites. Related: ReadRecordsAsync/ReadPluginsWithEntriesAsync have no production caller, so they are test support living on the production interface.
