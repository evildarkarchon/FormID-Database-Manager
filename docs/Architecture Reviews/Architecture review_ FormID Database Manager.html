Problem

Five modules append to the message lists. ClearMessageLists bypasses the dispatcher and lock that Add*Message uses. Because the sink adapters are private and nested, about 20 of the 38 UserWorkflowTests run a whole Processing Run just to check a one-line forward.

Solution

Move both sink adapters and the message-list rules into one module that UserWorkflow constructs and disposes. Test it directly against a ViewModel.

Wins

  • Locality: one message-list discipline
  • Sink adapters tested at their seam
  • UserWorkflowTests shrink to capture + dispose
  • ViewModel list setters can close
  • Leverage: three reporters, one writer
⚠ Amends ADR-0012 and ADR-0013, which place each adapter "private nested" in UserWorkflow. Both sinks stay. Only the adapter's home moves. Worth reopening because the nesting is what forces full-stack tests, and ADR-0013 left ownership of the message lists unanswered.

Solution

Hide Mutagen entirely behind the seam. It hands back domain facts (FormID, Entry) or a classified Plugin-read failure.
