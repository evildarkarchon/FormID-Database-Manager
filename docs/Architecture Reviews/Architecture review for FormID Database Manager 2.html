1 · Ask the Plugin List for its confirmation of a source

Before

After

Problem

Admission is pure, but its input embeds a PluginListState that only a live, async PluginList can construct (ADR-0009), and Admission re-derives the Plugin List's own source-matching rule.

Solution

Admission's input carries a small confirmation fact the Plugin List answers for the captured source. That fact is a closed union that tests can build directly.

Wins

  • Interface is the test surface
  • ~26 live Plugin List setups gone
  • Locality: source-matching lives in the Plugin List
  • One capture, no GameRelease/Source drift

Consistent with ADR-0009 (only the Plugin List constructs states) and ADR-0010 (admission is pure). It narrows what crosses the seam; it reverses neither.

After: the compiler holds the seam

Problem

Solution

Wins

  • Refactors stop paying a test tax
  • Fewer false failures
  • Seams visible in the code itself

Side findings (not deepenings)

  • Possible bug: unguarded RollbackAsync in the Plugin write (FormIdRecordStore.cs:353); see candidate 5.
  • Possible ordering risk (#60 area): MainWindowViewModel applies writes immediately when CheckAccess() is true and queues them otherwise. A UI-thread "Cancelling…" can therefore be overwritten by worker progress that was queued earlier. Processing Run Control's lock orders sink calls, not ViewModel writes. No test mixes the two paths. Found by reading, not reproduced.
  • Dead code: ImmediateThreadDispatcher (no references outside its file); FailedPluginReason; Store ReadRecordsAsync / ReadPluginsWithEntriesAsync have no production caller.
